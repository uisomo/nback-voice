# アクションカード 三段構成（学習 → 目的 → 具体アクション）— 設計

2026-09-06

## 1. 目的

現状のアクションカード画面は、プレイ中に「N手前のカードの目的は？」という
固定文だけを出す（`ActionGameScreen.tsx:279-297`）。問題は三つある。

1. **文脈が消える。** シーケンスの大目的（`seq.goal`）と全体の手数は intro
   にしか出ず、ラウンドが始まった瞬間に画面から消える。何のための手順を
   思い出そうとしているのか分からないまま答えることになる。
2. **問いが無意味。** 「N手前」は文字どおり `N` であって実際のラグですらない。
   さらに「何手前か」は覚える価値のある情報ではない。覚える価値があるのは
   「全7手のうち3手目が何で、なぜそれをするのか」である。
3. **目的欄が目的になっていない。** 17枚中13枚前後の `purpose` が
   「Xをして、Yを可視化する」という**手段の言い換え**で、判断ロジックを
   含んでいない。覚えても他の場面に転用できない。

本設計は、暗記に値する形へ作り替える。**学習 → 目的 → 具体アクション**の
三段構成にし、各段に n-back を入れ、回答はテキスト入力・即時開示・
ローカル採点にする。

## 2. 用語と階層 — ここが設計の中心

現データの最大の欠陥は、**手段の総称を目的の欄に入れていた**ことである。

> 「インテーク文書の優先グレード別要求」は**手段の総称**であって目的ではない。
> なぜそれをするのかと言えば、案件に取り組んでよいかを判断するプロセスがあり、
> 最重要な Deal Killer の項目から着手するので、まずそのような重要書類を
> 提出させ、顧客の負荷を減らすと共に、なるべく早く提出できるような依頼に
> 設計するためである。**この理由が目的である。**

この区別を型に落とす。

| 階層 | 格納先 | 意味 | 出題での役割 |
|---|---|---|---|
| 大目的 | `seq.goal` | シーケンス全体で達成したいこと | **全ステージで常時ヘッダに表示**。答えではない |
| 手段の総称 | `card.title` | その一手の呼び名 | 刺激。答えにはしない |
| 中目的 | `card.purpose` | **なぜその手段をとるのか**（判断ロジックを含む） | 目的ステージの答え |
| 小目的 | `subAction.purpose` | その一手を構成する各手順の「なぜ」 | 具体アクションステージの**問題文** |
| 具体アクション | `subAction.action` | 実際に何をするか | 具体アクションステージの答え |

展開例（ch02-a01）:

```
大目的      証拠格付けで情報開示の誠実性を見極める
 手段の総称  インテーク文書の優先グレード別要求
 中目的      案件に取り組んでよいかを判断するプロセスがあり、最重要な
             Deal Killer 項目から着手する。だから重要書類を先に出させ、
             顧客の負荷を下げつつ早く提出できる依頼に設計する
   小目的 a  Deal Killer になり得る論点を先に潰す
     具体 a  LPA・サイドレター・投資家リストを最優先で請求する
   小目的 b  顧客の負荷を下げて提出を早める
     具体 b  10営業日の期限を切り、様式を指定して往復を減らす
   小目的 c  出てこなかった場合の扱いを先に握る
     具体 c  未提出なら保守的代替推計を用いる旨をあらかじめ伝える
```

## 3. 採らなかった方針

**`RoundRunner` の再利用。** テキスト入力自体は既にある
（`AnswerInput = 'voice' | 'typed'`、`src/speech/typed.ts`）。しかし
`GameScreen` の typed 経路は `RoundRunner` のフェーズ制御・タイマー・
回答予算・カウントダウンと約100行絡み合っており（`GameScreen.tsx:466-536`）、
採点は typed でも Claude 非同期のままである。本設計が要求する
**タイマー無し・ローカル即時採点・即時開示・自己採点上書き・複数入力欄**は
そのどれとも噛み合わない。既存の音声ループに手を入れる危険を冒す価値がないため、
この画面専用の純粋な状態機械を新規に書く。

**`RoundRunner` に untimed モードを足す汎用化。** 唯一動いている音声ループを
この画面のために危険に晒す。不採用。

**音声スタックの削除。** しない。`src/engine/runner.ts`・`src/speech/*`・
`src/judge/*` は `GameScreen` が現役で使うため、そのまま残る。
`ActionGameScreen` が import をやめるだけである。

**適応N の廃止。** しない。`nextN()`（`src/engine/adaptive.ts:16`）は
`RoundEngine` に依存しない純粋関数なので、`drill.ts` から直接呼ぶ。
n-back 要素は三段すべてに入り、N は三段で共有する。

## 4. データ

### 4.1 スキーマ（`src/actions/actions.ts`）

```ts
export interface SubAction {
  id: string;              // "ch02-a01-s1"
  purpose: string;         // 小目的 — なぜこの一手順を踏むのか
  action: string;          // 具体アクション
  actionAccept: string[];  // 許容される言い換え
}

export interface ActionCard {
  id: string;
  order: number;
  title: string;           // 手段の総称
  purpose: string;         // 中目的（判断ロジックを含む「なぜ」）
  purposeAccept: string[];
  subActions: SubAction[]; // 具体アクションステージの出題単位
  category: Category;
  note?: string;
  layer2Skipped?: boolean; // true なら subActions は空。具体アクション段で飛ばす
}
```

**`action` / `actionAccept` は廃止する。** 出題単位が小目的になった以上、
カード直下に具体アクションが1本だけぶら下がる形は二重管理になる。

### 4.2 コンテンツ改訂

出典表示を事実に合わせる。書籍全文（`chapters_numbered/*.md` と 1.2MB の
`combined_*.md`）を検索した結果、`グレードA` `証拠グレード` `最弱証拠`
`欠落情報レジスター` `デ・スムージング` `デ・レバレッジ調整`
`アトリビューション` `痛み調整` はいずれも**0件**である（対照: `ファンド` は
2.md だけで78件ヒットするので検索は健全）。引用元とされる第2章は
商品類型の完全整理、第11章は担保・通知・執行の急所であり、内容が対応しない。

```
"credit": "『FundsFinanceの教科書』第2章 より"
        → "『FundsFinanceの教科書』をもとに構成"
```

カード本体は現状維持の判断。その上で執筆作業は次の三つ:

1. **17枚の `purpose` を書き直す。** 手段の言い換えを、判断ロジックを含む
   「なぜ」に変える。§2 の ch02-a01 が基準例。
2. **各カードに `subActions` を書く。** 現 `action` を小目的1つ目として移設し、
   小目的を書き足す。1枚あたり2〜4個を目安。
3. **`ch02-a07`（`layer2Skipped: true`、`action` が空）** は `subActions: []`
   のままとし、具体アクション段では引き続き飛ばす。学習段でだけ読める。

## 5. 採点（`src/actions/grade.ts` — 新規）

日本語には語境界がないので、**文字バイグラムの Dice 係数**で照合する。
外部依存なし・完全同期・API キー不要。

```ts
export const MATCH_THRESHOLD = 0.35;   // 実データで調整する
export function similarity(a: string, b: string): number;      // 0..1
export function gradeAnswer(input: string, accept: string[]): boolean;
```

- 正規化: NFKC → 空白と句読点を除去
- 模範解答と `accept[]` の全要素に対して照合し、**最大値**を採る
- 空入力は常に不正解
- 判定は `MATCH_THRESHOLD` 以上か否か

**自己採点で必ず上書きできる。** ローカル照合はあくまで初期値であり、
ユーザーが ✓／✕ をタップすれば結果はそちらが最終になる。閾値の誤りが
学習を壊さないための逃げ道であり、同時に「模範解答と自分の答えの差を
自分で考える」という学習でもある。

## 6. 状態機械（`src/actions/drill.ts` — 新規）

React に依存しない純粋モジュール。全同期。`await`・タイマー・ドレイン無し。

```ts
export type Stage = 'study' | 'purpose' | 'action';

export interface DrillStep {
  index: number;
  /** この設問が問う対象。null なら観察のみ（先頭N手） */
  targetIndex: number | null;
  /** 「全7個中 M個目」の M（1始まり）。常にカード単位で数える */
  ordinal: number;
  /** 「全7個中」の 7。常にカード枚数 */
  totalCards: number;
  /**
   * 具体アクション段でのみ非 null。そのカード内で何番目の小目的かを示す。
   * 序数表示をカード単位に保ったまま、小目的を特定するために要る。
   */
  subIndex: number | null;
}

export interface DrillState {
  stage: Stage;
  n: number;
  steps: DrillStep[];
  cursor: number;
  results: (boolean | null)[];
  checked: Set<string>;   // 学習段の緑チェック。セッション限り、採点に無関係
}
```

### 6.1 各段の出題単位と問い

| 段 | 出題単位 | 画面に出るもの | 入力欄 |
|---|---|---|---|
| 学習 | カード（ch02: 7） | 大目的／手段の総称／中目的／小目的→具体の入れ子 | 中目的・具体アクションの2欄 |
| 目的 | カード（ch02: 7） | 大目的／「全7個中 M個目」**のみ** | 中目的の1欄 |
| 具体アクション | 小目的を平坦化（ch02: 約20） | 大目的／「全7個中 M個目」／小目的の本文 | 具体アクションの1欄 |

**目的段で `title` を出さない**のは設計判断である。手段の総称を出すと
「名前を見て意味を答える」だけになり、n-back の保持負荷が消える。序数だけを
出せば「3手目が何だったか」を思い出す必要が残る。

**具体アクション段では小目的を問題文として出す**（ご指示どおり）。結果として
この段の保持負荷は下がり、手段想起のドリルになる。段ごとに負荷の質が違うのは
意図的である。

### 6.2 学習段の進み方

1. カード `i` を表示。枠をタップすると緑になり `checked` に入る（飾りであり、
   採点にも進行にも影響しない）
2. `i >= n` なら、直後にカード `i-n` について中目的と具体アクションを問う
3. `i < n` の先頭N手は観察のみ（`targetIndex: null`）

学習段の具体アクション欄には、カード直下の答えが存在しない（§4.1 で
`card.action` を廃止したため）。**そのカードの全 `subActions` の
`actionAccept` を合併した集合に対して照合し、模範解答としては具体アクションを
全て列挙して開示する。** 一手順でも言い当てれば正解とする — この段は
テストではなく学習であり、網羅性を要求する場ではない。

`layer2Skipped` のカード（`subActions` が空）は学習段でも**中目的の1欄のみ**を
出す。具体アクション欄は表示しない。

### 6.3 進行と適応N

- 「つぎへ」で**即座に**模範解答を開示し、ローカル判定の色（緑／赤）を付ける。
  同じ画面に自己採点の ✓／✕ を置き、押せば色が変わる
- 段の終了時に `answerScore = 正解数 ÷ 判定済み数`（自己採点の上書き後の値）を
  計算する。この画面には位置チャネルが無いので `roundScore` は `answerScore` に
  等しく、`nextN(answerScore, n, { positionScore: null, answerScore })` を呼ぶ。
  `positionScore` が `null` なので、既存ルールどおり **`answerScore` が満点の
  ときだけ N が上がり、0.5以下で下がる**
- 観察のみの先頭N手は判定対象に入らない。全ステップが観察のみだった場合
  （`n >= カード枚数`）は判定済みが0件になるので、N は変えない
- N は三段で共有し、次の段は更新後の N で始まる

## 7. 画面（`src/ui/ActionGameScreen.tsx`）

音声関連の import（`RoundRunner`・`ExpoSpeaker`・`ExpoListener`・
`TypedListener`・`JudgeQueue`・`ClaudeJudgeClient`・`useSpeechRecognitionEvent`・
`loadApiKey`）を全て外す。

**intro** — 現在の2チップを三段ナビに置き換える。矢印は進行順を示すだけの
非対話要素。

```
入力         学習  →  目的  →  具体アクション
N            −   2   ＋
             [ はじめる ]
```

**play** — ヘッダは全段共通で常時表示。

```
大目的  証拠格付けで情報開示の誠実性を見極める
全 7 個中  3 個目のアクション        2-back
─────────────────────────────
（段ごとの本文）

目的
[_______________________________]

            [ つぎへ ]
```

「つぎへ」後:

```
あなたの答え   証拠の強さをランク付けする
模範解答       全情報ソースにA〜Eを付与し委員会資料に明示する
███ 緑 ███                    自己採点  [ ✓ ] [ ✕ ]
            [ 次の問題へ ]
```

**results** — 段の正答率、更新後のN、次の段へ進むボタン。

## 8. 文言（`src/strings/index.ts`）

`promptPurpose` / `promptAction`（固定文）を削除し、文脈を組み立てる関数に
置き換える。ja / en 両方。

- `stageStudy` / `stagePurpose` / `stageAction`
- `grandPurposeLabel`（大目的）/ `midPurposeLabel`（目的）/ `subPurposeLabel`（小目的）
- `ordinalOf(m, total)` → 「全 7 個中 3 個目のアクション」
- `yourAnswer` / `modelAnswer` / `selfGradeCorrect` / `selfGradeWrong` / `nextQuestion`
