# Runbook

## PCで試す

実機ビルドの前に、Windows/WSL だけで確認できることが3段階ある。

### 1. テストスイート (今すぐ動く)

```bash
cd /mnt/c/Projects/nback-voice
npm test          # 22 suites / 307 tests
npx tsc --noEmit  # 型チェック
```

ゲームのルール、採点、未判定の扱い、2相ステップの進行、判定キューの
オフライン劣化まで、実機なしで全部ここで回る。**ただしTTSは即座に解決する
フェイクなので、発話にかかる実時間が絡む不具合はここでは絶対に出ない。**
実際そのクラスの重大バグが1件、全テストをすり抜けた。

### 2. バンドルが通るか (今すぐ動く)

```bash
npm run check:bundle   # ios と web を両方エクスポートする
```

**テストも型チェックも通るのにiOSのバンドルだけが落ちる**、という壊れ方が
実在する。`@anthropic-ai/sdk` の `client.mjs` が `node:fs` を import する
モジュールを引き込んでいて、React Native には Node の組み込みモジュールが
ない。Metro は到達しないコードも解決するので、アプリが一度も通らないパスで
バンドルが止まる。

`metro.config.js` が native (ios/android) のときだけ `node:` で始まる import を
空モジュールに差し替えて、これを塞いでいる。web は素通し — web には独自の
Node shim があり、普段使っているのはそちらだから。

実機もXcodeも要らない。**依存を足したとき、SDKのバージョンを上げたときは
必ず1回通すこと。** ブラウザで遊べていても、iOSのバンドルは落ちうる。

### 3. ブラウザで動かす

`expo-speech-recognition` はWeb Speech API、`expo-speech` はWeb Speech
Synthesis に対応しているので、**Chrome/Edge なら実際に遊べる**。web用の依存
(`react-dom` / `react-native-web` / `@expo/metro-runtime`) は導入済み。

`start-app.bat` の **[1]** が最短。中身は WSL 経由の `npx expo start --web`
(node_modules は WSL 側にあり Linux 専用バイナリを含むので、Windows の node
から直接叩くと web のバンドルが落ちる)。

**Firefox / Safari では回答を聞き取れない。** 音声認識があるのは Chrome と
Edge だけ。

Webで確認できること:
- 1ラウンド通しの動作、グリッドのタップ、適応的N、結果画面
- **APIキーが正しいかどうか** — 設定画面の「接続を確認」で一発で分かる
- 日本語の聞き取りが実際どの程度当たるか (Chromeの認識エンジン経由)

Webで確認できないこと (実機固有):
- iOSのオーディオセッション (質問2問目以降が小さくなる問題)
- `AVSpeechSynthesizer` の実際の発話速度とフェーズAの長さ
- Appleのja-JP認識精度、端末内認識の可否
- マイク許可のフロー

## iPhoneで使う

2通りある。**A は今日できる。B は Apple の審査待ちを挟む。**

### A. Safari + トンネル (Appleアカウント不要・今日できる)

web版をHTTPSで公開し、iPhoneのSafariで開く。

```bash
# 1) web を起動 (start-app.bat の [1] と同じ)
npx expo start --web

# 2) 別ウィンドウで HTTPS トンネル
cloudflared tunnel --url http://localhost:8081
```

出てきた `https://xxxx.trycloudflare.com` を **iPhoneのSafari** で開く。

**LANのIP (`http://192.168.x.x:8081`) では動かない。** マイクと音声認識は
セキュアなオリジンでしか使えないので、HTTPSのトンネルが要る。ここが唯一の
非自明な点。

根拠と限界(2026-08-20に確認):

- iOS Safari は **14.5以降** `webkitSpeechRecognition` を持つ。
  `expo-speech-recognition` の web 実装はこれをそのまま参照している。
- アプリは `continuous: false` で開始する。WebKitで報告されている
  「話し終えてもマイクが止まらない」不具合は主に `continuous: true` の話で、
  ここは踏んでいない。停止もアプリ側がタイマーで叩き、`settle()` が
  最後の一語を待つので、WebKitの発話終端検出に依存していない。
- **`interimResults` はWebKitで当てにならない。** 問題文の下の
  「認識中の文字起こし」が更新されないことがあるが、**確定結果は届くので
  採点は成立する**。壊れるのは表示だけ。
- web では権限APIは常に granted を返し、実際の許可はSafariが自分で聞く。
- 読み上げの解錠(ウォームアップのタップ)は元々iOS向けの仕組みで、
  Safariでもそのまま効く。
- 認識が使えなければ画面に `認識エラー: …` が出る。黙って失敗はしない。
- APIキーは設定画面に貼る。**再ビルド不要。**

### B. EAS実機ビルド (Apple Developer Program 必須)

ネイティブの認識・読み上げを使う本番の形。**Apple Developer Program
(年$99) の本人確認に24〜48時間かかることがあり、そこが律速。**

#### 前提
- Expoアカウント / Apple Developer Program メンバーシップ
- **APIキーを設定する。** 設定画面の「Claude APIキー」に貼るのが既定の方法で、
  再ビルドなしに差し替えられる(`.env` の `EXPO_PUBLIC_ANTHROPIC_API_KEY` は
  貼っていないときのフォールバックとして残っている)。
  キーが誤っていると Judge 呼び出しは全て401になり、設計上そのまま「未判定」に
  落ちるので、**壊れていることが画面から分からない**。設定画面の
  **「接続を確認」** が、それを唯一その場で言葉にする場所なので、
  キーを入れたら必ず一度押すこと。
- Node は v20.19.4 以上が望ましい (react-native / metro の要求。
  現在 v20.19.3 で警告が出る)

#### 一度だけ
```bash
npm install --global eas-cli   # 導入済み (eas-cli 22.x)
eas login
eas device:create              # iPhoneのUDIDを登録
eas build --profile development --platform ios
```
出てきたQRをiPhoneで読んでインストール。`eas.json` の `development`
プロファイルは設定済み。`app.json` の `ios.bundleIdentifier` は
`com.nbackvoice.app` — 変えるなら初回ビルド前に。

#### 毎日使う
```bash
npx expo start --dev-client
```
JSの変更だけなら再ビルド不要。ネイティブ依存を足したときだけ作り直す。

## 実機スモークテスト (Bの場合)

- [ ] マイクと音声認識の許可ダイアログが初回に出る
- [ ] 質問が日本語で読み上げられ、聞き取れる
- [ ] **質問2〜9問目が1問目と同じ音量** — iOSのオーディオセッションが
      認識開始後に出力を絞ることがある。ここが一番怪しい
- [ ] **質問が途中で切れない** — フェーズAは発話終了まで待つ設計だが、
      実際に最後まで喋りきってからマイクが開くか
- [ ] 読み上げ中にマイクが開いていない (回答に質問の語が混ざらない)
- [ ] **末尾が欠けない** — 回答窓の終わり際に2〜3語しゃべって、全部
      文字起こしされるか。`stop()` が確定前の暫定結果を拾う可能性がある
- [ ] マスをタップすると光り、次のステップでクリアされる
- [ ] 最初のNステップは出題のみで回答を求められない
- [ ] 末尾Nステップは無音・非表示で回答だけ求められる
- [ ] 結果画面に位置・回答の%と、未判定件数が出る
- [ ] **機内モードで1ラウンド完走でき、未判定表示になる** (誤答扱いにならない)
      端末内認識が効いていれば文字起こし自体は出るはず。出なければ
      サーバー認識にフォールバックしている
- [ ] 80%以上で次ラウンドのNが上がり、50%以下で下がる
- [ ] 設定のステップ長を変えるとテンポが変わる
- [ ] 起動ログに `on-device requested` / `server` のどちらが出るか
      (※ iOSは実際に使ったモードを返さないので、これは「要求した方」に
      すぎない。確実な判定は機内モードで認識が動くかどうか)

## シリーズと出題元

起動するとまず**シリーズ一覧**が出る。目的別のカテゴリの中に、内容由来の
タイトルを持つシリーズが並び、タップしたシリーズだけがそのラウンドの出題元になる。

- **金融の語彙を体に入れる** — コミットメントとキャピタルコール (15問) /
  NAVと担保の基礎 (12問) / ファンドの登場人物 (12問)。
  出典は『ファンドファイナンスの教科書』。
- **伝え方を変える** — 説得のデザイン (18問)。
  出典は『複雑な情報で相手を動かす』。
- **だれでも答えられる** — 標準問題 (内蔵) / 自分の問題。

9問に満たないシリーズは押せず「あと N 問」と表示する (自分の問題が9問に
届くまでがこれ)。

設定画面で切り替えるのは、出題元ではなく回し方だけ:

- **モード** — `位置＋質問` (既定) はグリッドのタップと口頭回答の両方を
  Nステップ遅延で行うデュアルN-back。`質問のみ` はグリッドを出さず、
  口頭回答だけのN-back。採点は回答チャネル単独になる。
- **標準問題のむずかしさ** — `やさしい`/`ふつう`。**標準問題にしか効かない。**
  自分で選んだシリーズを難易度で後から間引くことはしない。
- **自分の問題を編集** — 問題文と答えを1つずつ入力する。別の言い方をしても
  Claudeが正解と判断すれば、以後はその言い方も無料で通るようになる。
  問題を編集・削除すると、その問題について学習した別解は破棄される。
- **Claude APIキー** — 貼れば再ビルドなしで次のラウンドから効く。入れたら
  「接続を確認」を必ず1回押す (誤った鍵は401→未判定になり、画面からは
  故障が見えない)。

出題順はシリーズ内でラウンドごとにシャッフルされる。入力した順には出ない。

質問のみモードでオフラインだと、位置・回答のどちらのチャネルも得点が出ない。
このときNは据え置かれる (情報ゼロで難易度を動かさないため)。

出題プールが9問に満たないときはラウンドを始めず `問題が足りません` と表示する。

## N (ラグ) の決まり

**Nステップ前に出た質問に答える。** 1-back なら直前の質問、2-back なら2つ前の
質問。タップも同じで、Nステップ前に光ったマスを押す。

**Nはシリーズごとに別々に持つ。** 標準問題で3-backまで上げていても、金融の
シリーズを初めて選んだときは1-backから始まる。問題そのものの重さが違うのに
ラグだけ引き継ぐと、初回からいきなり壊れるため。現在のラグはシリーズ一覧の
各行に出る。

初期値は **1**。1ラウンドの得点が80%以上なら次ラウンドで N+1、50%以下なら N-1
(下限1)。設定で「Nを自動調整」を切ると固定値を選べる。

## ウォームアップ (ラウンドの始め方)

ラウンドは自動では始まらない。読み込み中に簡単な計算 (足し算・掛け算) が1問出るので、
答えをタップすると始まる。

これは飾りではない。**iOSはユーザー操作から出た発話でないと音を出さない**ため、
自動で始めると最初の2〜3問が無音のまま進んでしまう (フェーズAが発話待ちで
10秒のウォッチドッグまで延びるので、進みも遅くなる)。タップの瞬間に無音の発話を
1つ流して解錠している。正解でも不正解でもラウンドは始まる。

画面上部には常に `N-back ・ Nつ前の質問に答える` を出す。結果画面にも同じ表示が出る。

## 聞き取りの確認

ラウンド中、マイクが開いている間は認識中の文字起こしが問題文の下に出る
(無彩色。判定はまだ返っていないので色はつけない)。次のステップに進むと消える。

結果画面には採点した9ステップが1件ずつ並ぶ。

- 聞き取った内容が **緑=正解 / 赤=不正解 / 灰=未判定** で出る。
  灰の `（聞き取れず）` は認識が何も返さなかったステップで、これは未判定とは別物
  (判定に出していないので採点の分母にも入らない)。
- 右端の `位置 ○/×/—` はそのステップのタップ結果。質問のみモードでは出ない。

言い間違いではなく聞き間違いを疑うときは、ここの文字起こしを見る。

## 進捗をリセットする

アプリを削除して再インストールすると AsyncStorage ごと消える
(シリーズ別N・履歴・学習済み同義語・**設定したAPIキー** すべて)。

## ロールバック

JSのみの変更なら `git revert <commit>` の後
`npx expo start --dev-client --clear` で戻る。再ビルド不要。
ネイティブ依存を変えた場合のみ開発ビルドを作り直す。

## 既知の未解決事項

- 1ステップの長さは可変 (フェーズAが発話終了まで待つため)。1ラウンドは
  固定55秒ではなく、質問の長さで前後する。
- 採点コストは設計書§6.1の「¥2/ラウンド」を下限として見ること。
  opus-5は既定でthinkingが有効で、その分も課金される。
- App Store で不特定多数に配るなら、APIキーの扱いを先に決める必要がある。
  鍵はバンドル同梱ではなくなり、利用者が自分の鍵を設定画面に貼る形にできる
  ため、**その形なら配布にプロキシは要らない**。こちらの鍵で採点を提供する
  場合にだけ、プロキシと利用量の上限が要る。設計書§9を参照。
