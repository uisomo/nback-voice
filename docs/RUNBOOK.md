# Runbook

## PCで試す

実機ビルドの前に、Windows/WSL だけで確認できることが2段階ある。

### 1. テストスイート (今すぐ動く)

```bash
cd /mnt/c/Projects/nback-voice
npm test          # 16 suites / 140 tests
npx tsc --noEmit  # 型チェック
```

ゲームのルール、採点、未判定の扱い、2相ステップの進行、判定キューの
オフライン劣化まで、実機なしで全部ここで回る。**ただしTTSは即座に解決する
フェイクなので、発話にかかる実時間が絡む不具合はここでは絶対に出ない。**
実際そのクラスの重大バグが1件、全テストをすり抜けた。

### 2. ブラウザで動かす (未セットアップ)

`expo-speech-recognition` はWeb Speech API、`expo-speech` はWeb Speech
Synthesis に対応しているので、**Chrome/Edge なら実際に遊べる**。ただし
web用の依存がまだ入っていない:

```bash
npx expo install react-dom react-native-web @expo/metro-runtime
npx expo start --web
```

Webで確認できること:
- 1ラウンド通しの動作、グリッドのタップ、適応的N、結果画面
- **APIキーが正しいかどうか** — これが実機前に潰せる一番価値のある項目
- 日本語の聞き取りが実際どの程度当たるか (Chromeの認識エンジン経由)

Webで確認できないこと (実機固有):
- iOSのオーディオセッション (質問2問目以降が小さくなる問題)
- `AVSpeechSynthesizer` の実際の発話速度とフェーズAの長さ
- Appleのja-JP認識精度、端末内認識の可否
- マイク許可のフロー

## 実機ビルド (Task 12)

### 前提
- Expoアカウント / Appleアカウント
- **`.env` の `EXPO_PUBLIC_ANTHROPIC_API_KEY` を本物のキーに置き換える。**
  現在は `sk-ant-...` というプレースホルダのまま。放置するとJudge呼び出しが
  全て401になり、設計上そのまま「未判定」に落ちるので、**壊れていることが
  画面から分からない** (回答チャネルが永久に空欄になるだけ)。
- Node は v20.19.4 以上が望ましい (react-native / metro の要求。
  現在 v20.19.3 で警告が出る)

### 一度だけ
```bash
npm install --global eas-cli
eas login
eas build --profile development --platform ios
```
出てきたQRをiPhoneで読んでインストール。`eas.json` の `development`
プロファイルは設定済み。`app.json` の `ios.bundleIdentifier` は
`com.nbackvoice.app` — 変えるなら初回ビルド前に。

### 毎日使う
```bash
npx expo start --dev-client
```
JSの変更だけなら再ビルド不要。ネイティブ依存を足したときだけ作り直す。

## 実機スモークテスト

- [ ] マイクと音声認識の許可ダイアログが初回に出る
- [ ] 質問が日本語で読み上げられ、聞き取れる
- [ ] **質問2〜9問目が1問目と同じ音量** — iOSのオーディオセッションが
      認識開始後に出力を絞ることがある。ここが一番怪しい
- [ ] **質問が途中で切れない** — フェーズAは発話終了まで待つ設計だが、
      実際に最後まで喋りきってからマイクが開くか
- [ ] 読み上げ中にマイクが開いていない (回答に質問の語が混ざらない)
- [ ] **末尾が欠けない** — 回答窓の終わり際に2〜3語しゃべって、全部
      文字起こしされるか。`stop()` が確定前の暫定結果を拾う可能性がある
- [ ] マスをタップすると光り、次のステップでクリアされる
- [ ] 最初のNステップは出題のみで回答を求められない
- [ ] 末尾Nステップは無音・非表示で回答だけ求められる
- [ ] 結果画面に位置・回答の%と、未判定件数が出る
- [ ] **機内モードで1ラウンド完走でき、未判定表示になる** (誤答扱いにならない)
      端末内認識が効いていれば文字起こし自体は出るはず。出なければ
      サーバー認識にフォールバックしている
- [ ] 80%以上で次ラウンドのNが上がり、50%以下で下がる
- [ ] 設定のステップ長を変えるとテンポが変わる
- [ ] 起動ログに `on-device requested` / `server` のどちらが出るか
      (※ iOSは実際に使ったモードを返さないので、これは「要求した方」に
      すぎない。確実な判定は機内モードで認識が動くかどうか)

## モードと出題元

設定画面で切り替える。

- **モード** — `位置＋質問` (既定) はグリッドのタップと口頭回答の両方を
  Nステップ遅延で行うデュアルN-back。`質問のみ` はグリッドを出さず、
  口頭回答だけのN-back。採点は回答チャネル単独になる。
- **問題の出どころ** — `内蔵` (30問) / `自分の問題` / `両方`。
  自作問題が9問に満たないうちは `自分の問題` を選べず、あと何問必要かを表示する。
- **自分の問題を編集** — 問題文と答えを1つずつ入力する。別の言い方をしても
  Claudeが正解と判断すれば、以後はその言い方も無料で通るようになる。
  問題を編集・削除すると、その問題について学習した別解は破棄される。

出題順は内蔵・自作を問わずラウンドごとにシャッフルされる。入力した順には出ない。

質問のみモードでオフラインだと、位置・回答のどちらのチャネルも得点が出ない。
このときNは据え置かれる (情報ゼロで難易度を動かさないため)。

出題プールが9問に満たないときはラウンドを始めず `問題が足りません` と表示する
(自作問題を消した後や、難易度で内蔵が全部外れたときなど)。

## 進捗をリセットする

アプリを削除して再インストールすると AsyncStorage ごと消える
(適応的N・履歴・学習済み同義語すべて)。

## ロールバック

JSのみの変更なら `git revert <commit>` の後
`npx expo start --dev-client --clear` で戻る。再ビルド不要。
ネイティブ依存を変えた場合のみ開発ビルドを作り直す。
